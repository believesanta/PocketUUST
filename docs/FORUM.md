# Форум PocketUUST

## Что изменилось

- Лента с категориями, авторами, датами и счётчиками ответов.
- Ленты «Все обсуждения», «Мои публикации», «Избранное».
- Поиск по заголовку и тексту **во всей базе**, включая старые страницы. Регистр русских букв не важен.
- Сортировки «Сначала новые», «Популярные» (по числу лайков), «Без ответов».
- Один лайк на аккаунт у каждой темы и каждого ответа; повторный клик убирает лайк.
- Личное избранное хранится на сервере, доступно после входа с другого устройства.
- Ответы на тему и конкретному участнику с цитатой исходного сообщения.
- Автор может удалить свою тему или свой ответ. Удаление темы убирает и её ответы; перед действием открывается подтверждение.
- Гости читают форум; действия предлагают войти в аккаунт.
- Адаптация к узким экранам, светлой, тёмной и остальным существующим темам сайта. Исправлено наложение подписей верхней навигации на телефоне.

## Как обновить и запустить

1. Остановите старый сайт (`Ctrl+C`).
2. Распакуйте новую версию поверх файлов проекта. Сохраните существующую папку `.runtime`: в ней аккаунты, форум и расписание. Архив эту папку не заменяет.
3. Используйте Node.js **24.x** и выполните в папке с `package.json`:

```sh
npm ci
npm run dev
```

4. Откройте `http://127.0.0.1:5173` → «Форум».

Новые таблицы и поля добавляются автоматически при старте. Пересоздавать базу и заново импортировать уже существующие аккаунты не нужно. Настройки `.env` для форума не добавлялись. Парсер расписания по-прежнему требует Python 3.12+, отдельный Python-сервер не нужен.

Для совершенно новой установки без базы можно один раз запустить `npm run seed:test-accounts` **до** запуска сайта. Он добавит 128 аккаунтов из `test-accounts.txt`. Не запускайте импорт повторно, если эти логины уже существуют. Файл `seed-data/campus.sqlite` в корне архива — отдельная готовая база тестовых аккаунтов; основная программа не подменяет им рабочую базу.

## Где находятся данные и код

Основная база: `.runtime/campus/campus.sqlite` или каталог из `CAMPUS_DATA_DIR`.

| Часть                                                         | Файлы                                    |
| ------------------------------------------------------------- | ---------------------------------------- |
| Ленты и навигация                                             | `src/features/community/Forum.tsx`       |
| Карточки, разговор, публикация, подтверждение удаления, стили | `src/features/community/forum/`          |
| Схема, чтение, поиск, реакции и удаление                      | `services/campus/forum.mjs`              |
| HTTP API, сессии, права, ограничения и начисление баллов      | `services/campus/service.mjs`            |
| Проверки серверных сценариев                                  | `services/campus/tests/service.test.mjs` |

Данные форума не хранятся в `localStorage`. Интерфейс сбрасывает личное состояние при смене аккаунта. Сервер сам определяет автора из сессии, не доверяет присланному `userId` и проверяет владельца перед удалением.

## API

Все пути ниже имеют префикс `/api/campus`. Для изменения данных требуются сессия, JSON и допустимый Origin. API можно использовать для будущих клиентов через существующую систему авторизации; сервер не доверяет переданным клиентом признакам `canDelete`.

| Метод и путь                      | Назначение / тело                                  |
| --------------------------------- | -------------------------------------------------- |
| `GET /forum/topics`               | Лента, счётчики и категории                        |
| `GET /forum/topics/:id`           | Тема и страница ответов                            |
| `POST /forum/topics`              | `{category, title, body}`                          |
| `POST /forum/topics/:id/replies`  | `{body, parentId?}`; адресат только из той же темы |
| `POST /forum/topics/:id/like`     | `{liked: true/false}`                              |
| `POST /forum/replies/:id/like`    | `{liked: true/false}`                              |
| `POST /forum/topics/:id/bookmark` | `{saved: true/false}`                              |
| `POST /forum/topics/:id/delete`   | `{}`; только автор темы                            |
| `POST /forum/replies/:id/delete`  | `{}`; только автор ответа                          |

Параметры ленты:

- `scope=all|mine|saved` (последние два требуют входа).
- `category=all|study|freshmen|dorms|clubs|career|market|memes|ideas`.
- `q` — текст поиска, до 120 символов.
- `sort=new|top|unanswered`.
- `limit` — 1–50, по умолчанию 50; интерфейс запрашивает по 20 тем.
- `beforeId` — курсор следующей страницы. Для `sort=top` также нужен `beforeLikes`. Берите значения из `nextBeforeId` и `nextBeforeLikes`, не вычисляйте их на клиенте.

Ответ ленты: `{topics,total,hasMore,nextBeforeId,nextBeforeLikes,categories,stats}`. Счётчик `total` учитывает выбранные фильтры, `stats` и `categories` относятся ко всему видимому форуму.

Ответы загружаются от свежих страниц к старым через `beforeReplyId`; каждая страница упорядочена по времени от старых ответов к новым. При подгрузке предыдущих страниц клиент добавляет их сверху. Цитата доступна даже если исходный ответ на другой странице.

В объектах темы/ответа есть `authorId`, `likes`, `liked`, `canDelete`; у темы также `saved`. Почта автора не выдаётся в публичных данных. Числа лайков общие, флаги лайка/избранного относятся только к текущему посетителю. Передача желаемого состояния делает повторный запрос лайка/сохранения безопасным и не создаёт дублей.

## Удаление и совместимость

Миграция схемы **1 → 2** добавляет таблицы `forum_topic_likes`, `forum_reply_likes`, `forum_bookmarks`, поля `deleted_at`, `parent_id` и индексы. Переход из версии 0 также поддерживается. Существующие аккаунты, балансы, темы и ответы сохраняются.

При удалении содержимое очищается, запись помечается удалённой и исчезает из всех лент, поиска и API чтения. Удаление темы очищает её ответы и убирает закладки. Ссылка из чужого ответа на удалённый ответ показывает «Исходный ответ удалён», без прежнего текста. Идентификаторы и журнал начислений сохраняются: нельзя повторно получить дневные баллы удалением и созданием постов. За лайки и сохранение дополнительные баллы не начисляются.

Старые API чтения и создания совместимы: новые поля добавлены, обязательные поля не удалены. Сортировка популярного отражает лайки на момент запроса; при изменении рейтинга между страницами записи могут перемещаться. Клиент убирает дубли, полное обновление ленты даёт актуальный порядок.

## Проверки

```sh
npm test
npm run build
```

Серверные тесты проверяют повторные/одновременные лайки, приватность избранного, сохранение в SQLite, владельца публикации, удаление и недоступность удалённого содержимого, цитаты, ограничения начислений, поиск с русскими буквами, фильтры, пагинацию, миграцию старой базы и существующие сценарии аккаунтов.

Браузерные проверки выполнены на отдельной временной базе: вход, создание темы, лайки, избранное после перезагрузки, два аккаунта, ответы с цитатами, отмена/подтверждение удаления, поиск, светлая/тёмная тема, ширины 1440 и 390 px. Тестовые обсуждения из проверки не добавляются в вашу базу.

Сейчас это текстовый форум. Редактирование постов, вложения, уведомления, жалобы и интерфейс модераторов ещё не реализованы. Лента обновляется при открытии, действии или по кнопке обновления; WebSocket/push-обновлений нет.
