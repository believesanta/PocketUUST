# Работа с PocketUUST

## Структура

- `src/shared` — темы, главная страница и общая навигация.
- `src/features/navigation` — схема кампуса, маршрутизация и общежития.
- `src/features/schedule` — интерфейс расписания.
- `src/features/student-life` — карточки, новости, интересы, материалы и FAQ.
- `src/features/campus` — виджет, аккаунт, мини-игра и помощник.
- `src/features/community` — форум, объявления, мемы и отзывы.
- `src/features/services` — стипендия, контакты и история.
- `services/schedule` — Python-парсер, SQLite-кэш и HTTP API расписания.
- `services/campus` — аккаунты, серверные баллы, рейтинг и форум.
- `scripts` — новости, HTTP-сервер, проверки и упаковка.

## Перед изменением

Обновите свою ветку, проверьте текущие изменения и запускайте сайт из корня, где находится package.json. Изменения данных сопровождаются ссылками на первичный источник и датой проверки. Дата публикации новости не заменяет дату события.

Не меняйте идентификаторы карточек без причины: они используются в сохранённом и в защите от повторных начислений. Новые маршруты добавляйте только при подтверждении перехода на схеме.

## Перед передачей

```sh
npm test
npm run check
npm run build
```

Проверьте необходимые действия в четырёх темах, узкую ширину, ввод с клавиатуры, пустые результаты и сообщения об ошибках. Для проверки общего форума используйте два отдельных тестовых аккаунта. Не вводите пароль от университетской почты.

В репозитории нет пользовательской базы и секретов. Не добавляйте .env, .runtime, node_modules или внутренние рабочие файлы в Git и архив. Используйте `npm run package:case` для передачи проекта.

Код должен объяснять поведение именами функций и типов. Комментарии нужны для причин, ограничений источника и нетривиальных решений.
