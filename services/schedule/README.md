# Расписание PocketUUST

Сервис и Python-парсер взяты из предоставленного командного архива `PocketUUST (4).zip` и подключены к существующему сайту. Остальные разделы из архива не заменяли текущую реализацию.

## Запуск

Нужны Node.js 24 и Python 3.12+. Внешних Python-пакетов нет. Скопируйте `.env.example` в `.env`, если нужны настройки. На Windows задайте `SCHEDULE_PYTHON=C:/путь/к/python.exe`, когда `python` отсутствует в PATH.

```powershell
npm run build
npm start
```

Откройте http://127.0.0.1:3000, вкладку «Расписание». API также подключён в `npm run dev` (5173) и `npm run preview` (4173). Произвольный статический сервер не исполняет API.

## Источник и календарь

По умолчанию парсер получает публичные данные `https://dev.uust-time.ru/api/v/852972`, использует `?site=schedule` и сохраняет адрес и время получения. Для сверки в интерфейсе дана ссылка https://schedule.uust.ru/. Проверена загрузка каталога и реального расписания БМИ-ИВТ-103М, ID 13650, период 241.

Календарь задаётся настройками, а не выводится из названия группы: `SCHEDULE_PERIOD_ID=241`, `SCHEDULE_PERIOD_LABEL=2026/2027`, `SCHEDULE_FIRST_MONDAY=2026-08-31`, часовой пояс `Asia/Yekaterinburg`. Перед другим учебным периодом необходимо сверить и обновить эти значения. Номер учебной недели не является номером ISO-недели. Интерфейс показывает семь дней, включая воскресенье, и не придумывает время, аудиторию или день для записей, где их не указал источник.

## Как сохраняются данные

SQLite хранится в `.runtime/schedule/schedule.sqlite3`; для хостинга можно задать `SCHEDULE_DATABASE`. Каталог обновляется при запуске, расписания загружаются по выбору группы. Массовый импорт всех групп при запуске сайта отключён. Расписание выбранных групп повторно проверяется при запуске и смене календарного дня Уфы; истёкшие копии обновляются при обращении. TTL по умолчанию 24 часа, задаётся `SCHEDULE_TTL` и `SCHEDULE_CATALOG_TTL`. Кнопка «Обновить» явно запрашивает источник.

Одновременные запросы одного расписания объединяются; у источника одновременно работают не более двух запросов. Ошибка не стирает предыдущую копию. Ответ с `refreshing: true` повторно читается интерфейсом раз в 5 секунд, максимум 12 повторов, без повторного принудительного запроса к источнику. Смена группы/недели отменяет чтение. Дата получения и состояние сохранённой копии видны пользователю.

Браузер запоминает выбранную группу и последние восемь просмотренных недель. При недоступности сервиса может показать эти копии с явной отметкой. Это не полный автономный режим приложения: HTML и JS должен отдавать локальный сервер. Повреждённые записи браузера игнорируются. `SCHEDULE_OFFLINE=1` отключает запросы сервера к источнику; незагруженные данные вернут 503, а не фиктивно пустое расписание.

## Аудитории

«На карте» появляется при точном ручном сопоставлении или когда адрес явно указывает кампус в Уфе на Карла Маркса, 12, корпус обозначен однозначно и номер имеет формат 304 или 1-304. Поддержаны корпуса 1–4 и 6–9. Вставка УК-3-4, другие кампусы, буквенные аудитории и корпус 5 автоматически не сопоставляются. Для них показаны сведения источника.

Ручная привязка использует формат существующей навигации:

```powershell
npm run schedule:link-room -- --room-id 6593 --map-id 1-304
```

Проверяйте соответствие корпуса до привязки. Карта строит маршрут до корпуса и предполагаемого по номеру этажа; точной двери и планов этажей нет.

## Команды и проверки

```powershell
npm run schedule:sync -- --groups
npm run schedule:sync -- --group-id 13650
npm run schedule:backup -- --out ./tmp/schedule-backup.sqlite3
npm run test:schedule
npm run build
```

Файл резервной копии должен быть новым. Тесты используют временные базы и локальный тестовый источник, а не массовые запросы к университету. API находится под `/api/schedule/v1`: `/config`, `/groups/available`, `/groups?q=...`, `/schedules/group/ID?semester=241&week=4`, `/health`. По API доступны только GET-запросы; ручные записи выполняются CLI.
